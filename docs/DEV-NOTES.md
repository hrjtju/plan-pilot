# 开发笔记：本轮修改中解决与未解决的问题

> 记录区间：AI 代理故障修复 → 时间轴拖拽跟随滚动 → 甘特图交互升级 → 排期事件豁免。
> 配套排查手册见 `docs/TROUBLESHOOTING.md`。

## 一、已解决的问题

### 1. AI 报错的真凶是本地 API 代理传输层
- **现象**：使用 AI 功能偶发「请求失败」，误判为上游服务商问题。
- **根因**：dev server 未运行/HMR 重启窗口期，浏览器 fetch `/api/ai/chat` 直接 `TypeError`，此前被归一成模糊错误文案。
- **解法**：`src/ai/callPlanningAi.js` 将 fetch 异常包装为明确的「本地 API 代理不可达」致命提示；`usePlannerStore.js` 增加 `syncIssue` 探测（挂载 GET 重试 3×3s，防抖 POST 设置/清除标志）；`App.jsx` 渲染可关闭同步警告条。

### 2. startup.bat 双重损坏（编码 + 路径）
- UTF-8 中文注释在 GBK 命令行下乱码甚至中断解析 → 重写为纯 ASCII。
- 内嵌旧绝对路径失效 → 统一 `cd /d "%~dp0"`。
- **教训**：批处理文件不要混入非 ASCII 注释。

### 3. 时间轴拖拽跟随滚动（autoScroll）
- 纯数学抽离 `src/components/timeline/autoScroll.js`（速度梯度、帧位移 dt 封顶、钳制、最近可滚祖先查找），79 项单测覆盖。
- rAF 单循环 + ref 状态机，拖拽指针位置不触发 setState。
- **细节坑**：
  - `-0` 返回值会干扰比较与日志，区外边缘显式规范化为 `+0`；
  - 时间轴只露一条细缝时指针进入会误走「内部平移」分支并立即饱和卡死 → `visibleEnough` 门控（可见高 ≥ min(rect.h*0.5, 180) 才内部平移，否则交给页面级回卷）；
  - 画布平移时抓取点漂移 → 拖拽分钟差叠加 `panPx` 补偿；
  - 文本选区/文件拖拽误触发滚动循环 → `dragstart` 仅认 `.task-item.is-draggable`，`drop`/`dragend`/Esc 全部收尾。

### 4. E2E 测试基建的四个陷阱
- **种子被服务端水合覆盖**：应用挂载即 GET `/api/data` 用磁盘数据覆盖注入的 localStorage → 所有 E2E 用 `ctx.route("**/api/data", 503)` 隔离。
- **flex 容器吞噬注入内容**：向 `.workspace`（flex column）塞固定高度填充块会被默认压缩 → 需 `flex:0 0 <h>`；即便如此 React 渲染顺序仍会打乱测量，最终放弃「DOM 注入垫高」路线。
- **「时间轴能否被完全卷出视口」取决于其下方的内容量**而非上方 → 采用窄视口触发 `<1180px` 单列断点，利用访谈等天然长尾内容实现深度卷动（场景 A 从 2111px 拉回 0）。
- 运行环境：全局 playwright 需要 Windows 侧 `NODE_PATH`；bash 变量传不到 exe，用 `cmd.exe /c "set ...&& node ..."`。

### 5. 甘特图：条拖拽 + 时间刻度缩放
- 缩放档位表 `[14,30,60,90,180,365,730]` + 光标锚点保持，全部抽进纯模块 `src/planner/ganttZoom.js`（含阶梯步进、钳制、窗口裁剪 `clipBarToViewport`）。
- 重置（fit 模式）渲染结果与旧版静态百分比**逐像素一致**，保证零视觉回归。
- 条拖拽按天对齐、保时长，预览走 CSS `--bar-shift` 不触发重渲染；仅对显式声明了起止日期的目标开放，派生跨度给出解释性 tooltip 而非默默改数据。
- **CDP 合成滚轮特例**：自动化输入下 preventDefault 无法阻止默认页面滚动（甚至先于 JS 取消发生），组件内加了 280ms 时限滚动锁兜底；真实浏览器滚轮本就正常。
- bar 中心在首屏外时 Playwright 命中测试返回 null → E2E 必须 `scrollIntoViewIfNeeded` 后重新取坐标。

### 6. 自动排期的事件类豁免
- **需求**：事件类待办不受工作时段范围限制。
- **判定**：`planningSemantics.isEventLikeTodo` 复用产品自身的 `isBusySentence` 分类器（单一事实来源），排除购票流与会后整理流（它们有专门确认/锚定机制）。
- **测试反哺的一个真实缺口**：`买明天的高铁票`（动词与票务名词分离）能逃过 `isTicketPurchaseTask` 严格组合闸门进入豁免通道 → 谓词内补宽松守卫，不影响其他调用方的原语义。
- **架构上最隐蔽的一处**：排期核心里的豁免实现了，但 App 集成层的 `polishAiBlocks → clampToSegments` 管线会把所有块无条件裁回工作段，豁免块在最后一公里被「合法」裁掉。修法：`outsideWindow` 标记块的透传，而不是改集成层过滤逻辑。
- reconcile 层保留窗口/休息豁免但仍禁止与忙块重叠；`App.updateBlock` 让既有豁免块拖拽调整时不再报「超出工作时段」（新建仍严格）。

## 二、已知限制 / 未解决的问题

1. **甘特图超小内容的放大怪癖**：内容跨度 <7 天时点「放大」，`stepZoom` 会因档位下界先**扩大**到 7 天再逐步缩小；行为可预期但不符直觉。若需要支持 3/5 天档位需引入非均匀阶梯或动态插值（未做）。
2. **zoom 状态不持久化**：切换视图/刷新后甘特图回到「适应内容」。如需记住偏好要落 settings 或 sessionStorage（权衡过暂不做）。
3. **手动新建时段外任务块仍被禁止**：本次豁免只作用于「自动排期」及已有豁免块的拖拽微调。用户想手动把普通任务放到晚间仍需先改宽工作时段（产品层面是否放开留待讨论）。
4. **280ms 滚动锁的理论副作用**：仅在 CDP/平滑滚动的合成输入下才真正生效，真实滚轮几乎不会感知；极端情况下快速连续滚轮时页面会被轻钉约 0.28s，属可接受 trade-off。
5. **时间轴 E2E 场景 A 依赖单列断点**：未来若删除 `<1180px` 媒体查询或重排今日视图结构，「时间轴完全卷出」的前置会降级 SKIP（主断言可能失真），届时需改造成垫页脚方案（当时因 React 重排弃用的思路仍有价值：把填充块放在应用渲染树之外）。
6. **`buy-{verb}-split` 类豁免守卫只加在谓词内**：`isTicketPurchaseTask` 本身仍是严格定义，其他引用它的模块（如文案提示）对分离写法依旧按非购票处理；统一收敛需要动公共语义函数，影响面广，留待专项。
7. **本地文件双写一致性**：localStorage 与 `/api/data` 文件后端之间没有版本号/冲突合并，极端情况下（多标签页）以最后写入者为准——本次未触碰，仅记录。
